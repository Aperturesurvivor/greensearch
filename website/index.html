⚡ How it works

Every message runs through three steps before answering:

  • PromptShrink — strips filler from your question (watch the preview as you type)
  • Session cache — reuses a previous answer if you asked before
  • Routing — picks the shortest sufficient answer length
Routing thresholds

🌱 Sprout ≤12 words → ~2 sentences
🌿 Canopy 13–34 words → ~4 sentences
🌲 Forest 35+ words, complexity marker, or 2+ questions → ~6 sentences

How this demo works

Canned answers, not a live model

Every answer on this page is a pre-written template. There are 95 topics: six hand-written in three lengths (email follow-ups, APIs, workouts, backups, Portcullis firewalls, DNS) and 89 more, each one written once and cut to 2, 4 or 6 sentences depending on the route. No model reads your question. A question outside the library gets an honest "not in the library" reply, never a made-up answer.

What the steps really do

  • PromptShrink runs on your actual text: it removes filler and wordy phrases and leaves code blocks alone.
  • Routing picks Sprout, Canopy or Forest from word count, complexity words and question marks.
  • Session cache reuses an earlier answer when the trimmed question matches one you already asked. Regenerate skips the cache.

The numbers are estimates

  • Tokens are estimated as words × 1.33 (minimum 1). There is no real tokenizer.
  • CO₂e is tokens × 0.0018 g. That factor is an assumption, not a measurement of any data centre.
  • The baseline is assumed, not measured. It counts your original question plus the Forest (longest) answer, with no trimming, routing or reuse. It is not a measured ChatGPT or Gemini comparison. Published per-prompt figures for real models vary by 10× or more.

The live study is waiting for an API key

The repo includes a baseline study script (scripts/baseline_study.py) that can measure real token counts against a live model. It needs an API key, which this project does not have yet, so no live results exist. The repo's current BASELINE.md uses the offline canned provider and says so. No live numbers have been made up to fill the gap.

What would change with a live model

  • A backend. An API key can't safely sit in a browser page, so a small server would make the model calls.
  • A real tokenizer. Token counts would come from the model provider instead of words × 1.33.
  • A logprob cascade. A small model answers first, and the question goes to a larger model only when the small model's own token log-probabilities show low confidence. The Python package and the optional live backend do this; demo mode doesn't.
  • Finland hosting. Running in Google Cloud Finland (europe-north1, about 98% carbon-free energy) is a separate lever on top of token savings. This page runs on your device, not in Finland.
  • All the savings would need to be measured again. The percentages shown here would not carry over automatically.

Live mode (optional, off by default)

The Live mode switch sends each question to a GreenSearch backend at the URL you enter (default http://localhost:8000/api/chat, i.e. python server/app.py on your own machine). The backend holds the API key; this page never sees or sends one. It shrinks the question, checks its session cache, routes it, asks a small model first, escalates to a larger model only on low logprob confidence, trims the answer, and streams it back. Each live answer shows the model used, whether it escalated, cache hits, provider-reported tokens and latency. Live totals sit in their own LIVE row and are never added to the demo estimates. Measure baseline (off by default) makes a second, unconstrained call per message to measure real savings, which doubles API cost. Live answers aren't saved in localStorage; only the backend URL is, under greensearch-live-backend-url.

Privacy

In demo mode (the default) the whole demo runs in your browser from this one file. It makes no network requests, uses no analytics, and loads no outside fonts or images. Your chat is saved only in this browser's localStorage, under the key greensearch-demo-v1. The ✕ Clear button deletes it. The two external links on the page open only if you click them. Live mode is not browser-only: your questions go to the backend you configured, and from there to its model provider, whose data-retention policy applies.
